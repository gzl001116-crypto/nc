# NCstar

小说、漫画和影像站点。作者投稿，读者购买。金额以**分**为整数保存。NCstar 生成订单，但不收款；付款结果只认青澜支付站的签名回调。

## 运行

```bash
npm install
npm start
```

打开 <http://127.0.0.1:3000>。

示例账号（登录仍要验证码）：

- 作者：`lin@ncstar.local` / `ncstar-demo-8`
- 读者：`tang@ncstar.local` / `ncstar-demo-8`

没有配置 SMTP 时，验证码写在 [开发信箱](http://127.0.0.1:3000/dev/mailbox)。配置 `SMTP_HOST` 后只发邮件，开发信箱关闭。

```bash
npm test
```

## 作品

- 类型：小说、漫画、影像。
- 定时投稿：到点之前读者看不到，到点后自动发布。
- 预览：上传时选择**预览进度**或**预览内容**。进度按比例截断正文和漫画页；内容只展示作者另写的预览。
- 价格：页面按元输入，最多两位小数，入库为整数分。

## 热度

热度 = 点赞人数 / 浏览人数，从高到低。

- 只有浏览人数 **超过 100** 的作品进入热度栏，不超过的不显示。
- 一个账号只贡献一次浏览，未登录的访问不计。
- 点赞同样按账号去重。

## 订单与青澜

创建订单只写入「待支付」，并带上签名后的收银台地址。用户从支付站跳回订单页时，页面只展示数据库里的状态，不会把订单改成已支付。

回调使用双方约定的 `QINGLAN_SHARED_SECRET` 做 HMAC-SHA256。参与签名的字段按键名排序，键和值分别做 `encodeURIComponent`，再用 `&` 连接。

订单状态：待支付、已支付、已退款。同一条已支付回调重复到达时，作者收入只记一笔。

作者账本每一笔包含作品、订单、总额、平台分成、作者所得、时间和待结算 / 已结算。分成在入账时用整数分计算，默认平台 20%（`PLATFORM_FEE_BPS=2000`）。已结算以青澜的结算通知或主动查询为准。

结算账户、提现和打款在青澜支付站，用注册时绑定的同一个客户编号打开。NCstar 不向银行卡打款。

本地演示时，青澜收银台和 NCstar 跑在同一个进程里，但付款状态只在验签回调里更新。把 `QINGLAN_BASE_URL` 指到外部支付站时，沿用同一套签名字段即可。
